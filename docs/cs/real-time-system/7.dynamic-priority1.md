## Time-demand Schedule
=> 이미 필요충분조건이 있는데 왜?
=> 적용할 수 없는 경우가 있고(deadline<=period, deadline inflation으로 적용 가능하나 충분조건이 됨) 더 많은 정보 제공

1 일반적인 경우

$L >= D[0,L] = \sum \lfloor {L \over P} \rfloor e_i$

2 deadline < period

deadline 간의 간격도 p로 형성됨을 이용  
phase=0이 아니라 phase=D1로 시작하면, L -> L-D
그리고 phase=D1로 앞당긴동안 task가 1개 수행되므로 +1

$D[0,L] = \sum (\lfloor {L - D \over P} \rfloor + 1)e_i$

hyper period까지, 첫 시작(d1)부터

3 NPS(Non-Preemptive code Section)

priority는 absolute deadline으로 결정됨

low priority 작업이 먼저 실행되는 경우가 문제

$b_i = max^n_{j=i+1}NPS_j$

$\sum^n_{j=1} {e_j \over p_j} + {b_i \over p_i} <= 1$
task by task check (only for task $i$)

$\sum^n_{j=1} {e_j \over p_j} + max^n_{j=1}{b_i \over p_i} <= 1$
single check (for all tasks)
