## Write Policies

write
hit miss
write through / write back / write allocate / no write allocate

- write through
구현이 쉬움
쓰기가 읽기보다 느림
가장 낮은 단계의 메모리도 캐시와 일관성이 항상 유지됨

- write back
구현이 어려움(dirty bit)
읽기 쓰기가 비슷한 속도로 동작 -> 읽기를 할때 dirty bit이 있으면 쓰기가 먼저 수행됨
가장 낮은 단계의 메모리가 캐시와 일관성이 항상 유지되지 않음

- Write allocate
The block is loaded into the cache on a write miss

- No write allocate
The block is modified in the lower-level memory and not loaded into the cach
